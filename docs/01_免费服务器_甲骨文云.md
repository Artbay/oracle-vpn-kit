# 01 免费服务器：甲骨文云（Oracle Cloud）Always Free

> 核对时间：2026 年下半年。Oracle 的条款、界面和可用区会变，**以官方页面为准**。下文标注「官方」的均附链接；标注「经验」的是实际部署中观察到的情况，标注「未核实」的请自行确认。

## 1. 免费额度里与本方案相关的部分（官方）

- 所有账户（免费或付费）在**主区域（home region）**都有一组终身免费的 Always Free 资源。
- **VM.Standard.E2.1.Micro（AMD）最多 2 台**；E2.1.Micro 在多可用域区域里只能建在其中一个可用域。
- 每台 Micro：1 个 VNIC + 1 个公网 IP，公网带宽**最高 50 Mbps**。
- 块存储共 200 GB，每个启动卷最少 47 GB。
- **每月 10 TB 出站流量**免费。
- Free Tier 账户最多 2 个 VCN。
- 来源：[Always Free Resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)

> 本方案对配置要求很低，1 台 E2.1.Micro 即可。Ampere A1（Arm）额度更大，但常出现「out of host capacity」（经验）。

## 2. 注册

1. 打开 <https://www.oracle.com/cloud/free/> → **Start for free**。
2. 填写邮箱、国家/地区，验证邮箱；姓名、地址、手机号**如实填写，与卡账单信息一致**。
3. **选择主区域（Home Region）**，见下一节，**选了就改不了**。
4. 绑定信用卡做身份验证（见第 4 节）。
5. 开通后可能要等几分钟所有服务和区域才可用。

官方规则（[Free Tier FAQ](https://www.oracle.com/cloud/free/faq/)）：

- **禁止创建或尝试创建多个免费账户**；联系与账单信息必须准确有效。
- **账户闲置 30 天以上**可能被视为弃用，进而被暂停或终止。
- 违反上述要求或 Cloud Services Agreement 可能导致账户被暂停或终止。

## 3. 选主区域（不能更改）

- 官方：主区域保存账户和身份（IAM）资源，**租户开通后不能更改**（"Oracle assigns your home region and you can't change it."）。来源：[Managing Regions](https://docs.oracle.com/en-us/iaas/Content/Identity/regions/managingregions.htm)
- Always Free 计算实例**只能建在主区域**（[Always Free Resources](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)）。所以选主区域 = 选你免费机器的机房。
- 建议（经验）：选离你近、对你网络线路友好的区域；热门区域容易没有容量，开不出实例时可以换可用域或隔一段时间重试（官方 FAQ 也这么建议）。
- 若首选区域在注册页不可选，官方建议选相邻区域（FAQ）。

## 4. 信用卡验证（不会扣 Always Free 的钱）

官方 FAQ 原意：

- 需要信用卡/借记卡做**身份验证**；Oracle 可能定期验证卡片有效性，产生临时「预授权」冻结，**通常 3–5 天内由银行解除，不产生实际扣款**。
- 接受信用卡及「功能等同信用卡」的借记卡；**不接受带 PIN 的借记卡、虚拟卡、一次性卡、预付卡**。
- 新账户通常还有 30 天、US$300 的试用额度（部分国家/地区）。

> **不要随便升级到 Pay As You Go（按量付费）**。官方说明升级后 Always Free 资源仍免费，只对超出免费额度的用量收费——但升级后误开付费资源就会真实扣费。确实需要再升级，并先设好预算提醒。

## 5. 创建 VCN 和实例

1. 控制台 → **Networking → Virtual cloud networks → Start VCN Wizard → Create VCN with Internet Connectivity**（会同时建公有子网、Internet Gateway、路由表和默认安全列表）。
2. **Compute → Instances → Create instance**：
   - Image：**Canonical Ubuntu** LTS（x86_64，22.04 或更新的 LTS；脚本基于 apt + systemd）。
   - Shape：**VM.Standard.E2.1.Micro**，确认有 **Always Free-eligible** 标签。
   - Networking：选刚建的 VCN 的**公有子网**，保持 **Automatically assign a public IPv4 address** 勾选。
   - SSH keys：选 **Generate a key pair for me** → **Download private key**（以及公钥）。**私钥只出现这一次，务必保存好**，权限 `chmod 600`，不要放进 git、网盘共享目录或聊天里。
3. 创建完成后，用 `ssh -i <你的私钥文件> ubuntu@<VPS_IP>` 登录（Ubuntu 镜像的默认用户是 `ubuntu`）。

## 6. 公网 IP：临时（Ephemeral）与保留（Reserved）

官方（[Public IP Addresses](https://docs.oracle.com/en-us/iaas/Content/Network/Tasks/managingpublicIPs.htm)）：

- 创建实例时默认分配的是**临时公网 IP**：实例停止时仍保留；**实例删除时随之删除**；不能移到别的私有 IP；**删除（unassign）就没了**。
- **保留公网 IP**：可以随时解绑再绑到别的实例，解绑后回到你租户的保留 IP 池。
- 一个公网 IP 创建后**类型不能改**：不能把现有临时 IP「转成」保留 IP。

换 IP 的两种做法：

- **换一个新的临时 IP**（IP 被网络封锁想换时常用）：实例 → Attached VNICs → 选 VNIC → IP administration → 主私有 IP 的 **Edit** → Public IP type 先选 **No public IP** 保存，再改回 **Ephemeral public IP** 保存，就会拿到一个新 IP。参考：[Assigning an Ephemeral Public IP](https://docs.oracle.com/iaas/Content/Network/Tasks/assigning-ephemeral-public-existing-private-ip.htm)
- **改用保留 IP**（希望 IP 长期固定）：Networking → IP management → Reserved public IPs → Reserve；然后在主私有 IP 的 Edit 里先改为 No public IP，再选 Reserved public IP 绑定。参考：[Assigning a Reserved Public IP](https://docs.oracle.com/en-us/iaas/Content/Network/Tasks/reserved-public-ip-assign.htm)

> **未核实**：保留公网 IP 在纯 Always Free 账户里的数量上限与是否计费，请在控制台 Limits 页面和价格表确认后再用。
> 换 IP 后：改 `.env` 的 `VPS_IP` → 重新生成订阅 → 重新发布（见 [03_客户端使用](03_客户端使用.md)）；CDN 节点不受影响。

## 7. 安全列表（云防火墙）入站规则

VCN → Security Lists → Default Security List → **Add Ingress Rules**，Source CIDR `0.0.0.0/0`：

端口都来自你的 `.env`（`scripts/gen_secrets.sh` 随机生成）：

| 协议 | 端口 | 用途 |
|---|---|---|
| TCP | 22 | SSH（向导默认已有） |
| TCP | `XHTTP_PORT`（默认 443） | Xray XHTTP+Reality |
| TCP | `REALITY_PORT` | Xray Reality |
| TCP | `SUB_PORT` | 订阅 |
| UDP | `HY2_PORT` | Hysteria2 |
| UDP | `HY2_HOP_START`-`HY2_HOP_END` | Hy2 端口跳跃 |
| UDP | `TUIC_PORT` | TUIC |
| ICMP | — | ping（可选） |

参考：[Security Lists](https://docs.oracle.com/en-us/iaas/Content/Network/Concepts/securitylists.htm)

## 8. Ubuntu 镜像自带的 iptables REJECT（经验）

OCI 的 Ubuntu 镜像在主机上自带一套 iptables 规则：`INPUT` 链末尾有 `-j REJECT --reject-with icmp-host-prohibited`，**只放行了 SSH**。所以：

- **安全列表放行了还不够**，主机 iptables 也要放行，并且规则要插在 REJECT **之前**；
- 本仓库脚本统一用 `iptables -I INPUT 1 ...` 插入，再 `netfilter-persistent save` 写入 `/etc/iptables/rules.v4`；
- **不要删除** `InstanceServices` 链里 169.254.x.x 的规则（Oracle 注释说明它们关系到实例的元数据、iSCSI 等服务）；
- 不建议直接 `ufw enable` 或清空 iptables，容易把 SSH 锁在外面。

## 9. 闲置回收（官方）

[Always Free Resources → Reclamation of Idle Compute Instances](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)：在 **7 天**内同时满足以下条件，Always Free 实例可能被视为闲置并**被回收**：

- CPU 利用率 95 分位 **< 20%**；
- 网络利用率 **< 20%**；
- 内存利用率 **< 20%**（**仅适用于 A1**）。

另外 FAQ 提到：资源一旦被回收**无法恢复**。

建议：

- 日常真正在用就不太会触发；长期不用前心里有数，**配置都在本仓库 + `.env`，被回收也能重建**；
- 不建议为了「保活」去跑无意义的耗 CPU/流量脚本（可能违反条款，也浪费资源）——这一点是建议，不是官方说法。
